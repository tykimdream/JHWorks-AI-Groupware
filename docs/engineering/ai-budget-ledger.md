# AI 비용 예약·정산 기반 — M2-02A

이 문서는 서버 예산 원장의 계약이다. [M2-02B2](public-expense-ai-contract.md)는 opt-in 경비 provider와
화면을 연결한다. 기본 OFF·원격 미적용이며 공개 AI는 계속 OFF다.
M2-02 전체 완료, 실제 가격 검증, 외부 과금의 절대 상한 보장을 뜻하지 않는다.

## 비용과 호출의 수명

1. 서버 인증에서 확인한 방문 공간 ID와 모든 유료 단계의 최대 비용으로 `reserve`한다.
2. 별도 DB 세션에서 예약이 커밋된 뒤에만 provider를 호출해야 한다.
3. 서버가 확인한 실제 비용으로 `settle`한다. 원장 함수를 클라이언트의 환불 API로 노출하지 않는다.

단위는 정수 micro USD(1 USD = 1,000,000)다. 일/월 비용, 전체 일별 admission,
공간별 일별 admission, 전역 동시 요청 한도는 모두 필수이며 운영 기본값은 없다.
admission은 예약 시도 중 허용된 건수이며 실제 모델 호출 수와 다르다. 0원 정산도 횟수는 반환하지 않는다.

`ai_budget_counters`는 전역 상태와 서울 기준 일·월·공간별 일 카운터를 가진다.
`ai_budget_reservations`는 예약 당시 기간 키·최대 비용·상태·정산 비용·생성 시각을 보관한다.
원문, 응답 본문, 키, 사용자 정보는 저장하지 않는다. 공간 키는 서버 ID의 SHA-256 파생값이다.
해시 키는 인증이 아니므로 호출자가 공간의 유효성·권한·만료를 먼저 검사해야 한다.
공간 삭제로 전체 비용 이력을 초기화하지 않도록 업무 데이터에 대한 cascade FK는 두지 않는다.

## 동시성과 날짜 경계

모든 변경은 기간과 무관한 `global` 행부터 잠근다. PostgreSQL은 행 잠금,
SQLite는 첫 upsert의 쓰기 잠금을 이용한다. 이후 기간 키는 일정한 순서로 잠근다.
예약 비용과 누적 비용의 합이 일/월 한도 안에 있을 때만 admission을 커밋한다.
사업 데이터의 부분 커밋을 막기 위해 이미 트랜잭션이 시작된 세션은 거부한다.

잠금을 얻은 뒤 DB 시각을 읽고 서울의 날짜·월을 정한다. 성공한 admission보다 DB 시계가
뒤로 가면 새 예약을 거부한다. 자정·월초를 지나도 전역 동시 요청 수는 초기화되지 않는다.
정산은 예약 당시 기간에 반영하므로 월말 요청이 다음 달 예산을 잘못 환불하지 않는다.

## 정산과 실패

| 결과 | 상태와 동작 |
| --- | --- |
| 실제 비용 ≤ 예약 | `SETTLED`: 실제 비용 누적, 차액 반환, 동시 요청 해제 |
| 비용 확인 불가 | `UNCERTAIN`: 최대 예약 비용 전액 누적, 동시 요청 해제 |
| 실제 비용 > 예약 | `OVERRUN`: 실제 비용 기록, 전역 신규 예약 동결 |
| 같은 정산 재전송 | 비용·상태가 같으면 같은 결과, 중복 차감/해제 없음 |
| 정산 내용 변경 | 409, 기존 원장 유지 |
| DB 장애 | 503으로 신규 호출 차단, 내부 진단을 사용자에게 반환하지 않음 |
| 프로세스 중단 | 예약·슬롯 유지, 자동 만료/자동 환불 없음 |

중단된 예약은 사용 가능성을 낮추지만 지출 한도를 되돌리지 않는다. 운영 복구 절차 없이
공개하면 슬롯이 소진될 수 있다. 시간만 지나면 무료로 환불하는 방식으로 복구해서는 안 된다.
외부 제공자의 잘못된 사용량·가격 변경·예약 산정 누락·집계 지연까지 절대 과금 상한으로 보장하지 않는다.
GCP Cloud Run spend cap과 이 원장은 서로 다른 예산이다.

## 마이그레이션과 검증

`a14c7e2d903f`는 두 테이블만 추가한다. 원장이 하나라도 존재하면 downgrade를 거부하며
offline SQL downgrade도 거부한다. 초기의 빈 원장만 제거할 수 있다. 원격 DB에는 적용하지 않았다.
기존 운영 SQL·fixture preflight는 배포된 `f30c9a71b624`를 계속 고정한다.
CI는 이 과거 상태 재현과 최신 head의 전용 migration/runtime 역할·신규 테이블 권한을 별도로 검증한다.

```sh
cd apps/api
uv run pytest tests/test_ai_budget.py tests/test_ai_budget_migration.py
# 전용 loopback PostgreSQL 환경에서만 실행; CI의 postgres job에 포함
uv run pytest tests/test_postgres_ai_budget.py
```

검증은 별도 연결 경합, 중복 정산, 날짜/월 경계, 시계 역행, DB 실패, 알 수 없는 비용,
초과 비용 동결, 기존 업무 세션 보존, 마이그레이션의 업무 행 보존과 원장 삭제 거부를 포함한다.
로컬 PostgreSQL이 없으면 해당 4개는 skip되며 통과했다고 표현하지 않는다.
