# 경비 정산 신규 사용자 과제 — M0-02 준비

상태: 절차·빈 기록 양식 준비, **신규 참가자와 실제 측정은 대기**.
기존 휴가 실험 문서/CSV는 보존한다. 자동 테스트 시간을 사람의 완료 시간으로 사용하지 않는다.

## 과제와 조건

“가상 CES 협력사 방문에 사용한 교통비17만원을 코레일 경비로 정산하고 승인 결과를 확인하세요.”
합성 지출일2026-08-24, 증빙 참조 RCP-CES-001. 직접 작성과 AI 경로에 같은 사실을 제공한다.
서버 날짜가 이 지출일 이후인지 확인하고, 제품/정책/데이터 revision·브라우저·viewport를 고정한다.

수동 조건은 공개 홈→초안 저장→제출→역할 전환→승인→작성자 결과 확인이다.
AI 조건은 실제 AI 경로가 준비된 뒤 같은 사실의 자연어 요청→질문→미리보기 저장→동일한 이후 절차다.
공개 AI OFF 상태를 실패한 모델 결과로 계산하지 않으며 현재는 수동 경로만 실험 가능하다.

## 진행

- 신규 사용자3~5명을 초기 목표로 하되 실제 확보한 수를 그대로 보고한다. 개발자 자체 점검은 별도 조건으로 적는다.
- 시작 신호부터 올바른 승인 결과 확인까지 측정한다. 진행자의 도움·사용자 중단·실패도 기록한다.
- 각 조건은 새 합성 공간에서 시작한다. AI/수동 비교 시 순서를 번갈아 배정하고 연습과 본 측정을 구분한다.
- 같은 참가자의 반복 과제는 학습 효과가 있으므로 독립된 신규 사용자로 세지 않는다.
- 시간·성공·오류·수동 수정 필드·도움 요청·막힌 단계를 기록한다. 실패한 trial을 분모에서 빼지 않는다.
- 원문 프롬프트·실제 영수증·이름/이메일·세션/키를 저장하지 않는다. 익명 ID와 비식별 관찰만 남긴다.
- UI 변경 전후의 revision과 조건을 고정하고 재측정한다. 참가자가 없으면 기다리는 상태를 유지한다.

## 기록과 보고

[빈 CSV](expense-task-study.csv)의 한 행은 한 trial이다. 미측정 값은 빈칸이고 0이 아니다.
각 trial의 시작/종료·성공 여부·오류 분류와 전체 성공/시도 수, 완료 시간의 중앙값/범위를 함께 보고한다.
적은 표본의 탐색 결과이며 일반 기업의 생산성 향상으로 일반화하지 않는다.
추가 보조 계측/외부 analytics는 도입하지 않았다.
