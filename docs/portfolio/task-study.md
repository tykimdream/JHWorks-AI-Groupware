# 휴가 작성 작업 비교 절차

상태: **사람의 작업 시간 측정 대기**. 브라우저 테스트의 실행 시간은 사람의 업무 완료 시간이 아니다.
이 문서는 가상 데이터와 개발자 자체 측정 또는 동의한 참여자의 사용성 실험을 위한 절차다.

## 조건

- 동일한 Git revision, 브라우저, viewport, 네트워크, 로그인 계정과 DB snapshot을 사용한다.
- 시작 화면은 로그인된 `/attendance`, 종료는 저장된 LEAVE DRAFT 상세 화면이다. 로그인 시간은 제외한다.
- 과제는 “같은 팀 일정에 충돌하지 않는 2일 연차를 다음 주에서 찾고 초안으로 저장한다”로 고정한다.
- Asia/Seoul의 기준 날짜, 검색 범위, 해당 계정의 잔여 연차, 정책 버전과 일정 snapshot을 기록한다.
- 가상 seed에는 2026년 9월 충돌 일정이 있다. 충돌 실험은 명시적 2026-09-01~30 과제와 고정된
  가상 기준일을 사용한다. 현재 날짜의 자연어 과제와 과거 fixture를 섞지 않는다.
- 테스트용 DB 복사본에서만 수행한다. 원래 개발 DB를 지우지 않는다. 매 trial은 같은 snapshot의 새 복사본으로
  시작한다. DRAFT 저장은 연차 예약이 아니지만 목록 수와 학습 효과도 통제해야 한다.
- AI 조건에는 실제 모델, prompt version, RAG 색인 상태, timeout과 token usage를 기록한다.
  fake provider를 사용한 경우 `provider=fake`로 기록하고 모델 정확도나 실제 지연으로 해석하지 않는다.
- 외부 API 비용이 드는 실험은 별도 명시적 실행 대상이며 자동 검증에서 호출하지 않는다.

## A: 현재 제품의 수동 작성 경로

1. 수동 휴가 후보 탐색에 기간과 희망 일수를 입력한다.
2. 원본 확인 영역에서 가용/사용/대기 연차와 회사/부서/팀 휴가 일정을 읽는다.
3. 날짜별 근거와 후보를 비교하고 날짜를 선택한다.
4. 기존 전자결재 양식에 자동 입력된 날짜를 확인하고 제목, 본문과 필요한 내용을 작성한다.
5. Draft 저장을 누르고 상세 화면의 유형, 날짜, 차감과 상태를 확인한다.

이 baseline도 기존 deterministic 후보 엔진과 날짜 자동 입력을 사용한다. 종이나 별도 캘린더로 날짜를
완전히 수작업 계산하는 업무와 비교한 것으로 표현하지 않는다.

## B: AI 보조 작성 경로

1. 자연어 과제를 입력하고 구조화된 절대 날짜를 확인한다.
2. 필요하면 후속 질문에 답하고, 서버가 계산한 후보와 근거를 읽는다.
3. 날짜를 명시적으로 선택한다.
4. 초안의 날짜, 차감, 가용 연차, 결재자와 정책을 확인한다.
5. 명시적으로 저장을 누르고 같은 기준으로 DRAFT 상세를 확인한다. 제출하지 않는다.

## 반복과 순서

- 참여자별 연습 A 1회, B 1회를 제외하고 각 방식 5회씩, 5쌍을 수행한다.
- 첫 참여자는 AB/BA/AB/BA/AB, 다음 참여자는 BA/AB/BA/AB/BA 순서로 실행한다.
- 1명의 개발자가 측정했다면 개발자 자체 측정 n=1이라고 명시한다.
- 정상 과제 5쌍과 별도로 잔여 부족, 필수 일정 충돌, AI 장애를 각 경로 1회씩 수행한다.
- AI 장애에서 수동 fallback으로 완료한 경우 `fallback=true`로 보존한다. 느리거나 실패한 trial도 삭제하지 않는다.

## 기록과 해석

`task-study.csv` 한 행을 한 trial로 사용한다. 모르는 값은 빈칸으로 남기고 0으로 대체하지 않는다.

- 완료 시간: 진행자가 시작 신호를 준 시점부터 올바른 DRAFT 상세 확인까지의 실제 시계 시간. 실패는 성공으로 계산하지 않는다.
- 화면 이동: pathname 변경 수. 스크롤, 같은 페이지의 anchor 이동과 modal 열기는 별도 인터랙션으로 기록한다.
- 수동 입력: 사용자가 값을 채우거나 바꾼 필드 수. 자연어 요청 1개는 1개 필드로 기록한다. 자동 입력은 제외한다.
- 오류: 잘못된 날짜/유형/차감/상태 저장, 필수 정보 누락, 요청 실패를 구분해 기록한다.
- 성공률: 올바른 DRAFT 수 / 시작한 과제 수. 사용자 중단과 provider 오류도 분모에 남긴다.
- 호출 성공률: 실제 trace의 성공 호출 / 전체 시도 호출. 휴가 상담의 structure와 RAG는 일반 업무 Assistant의
  Function Calling 호출 수와 구분한다. fake token/latency는 성능 지표에 합산하지 않는다.
- latency/tokens: 서버가 관측한 실제 provider 값. 전체 완료 시간, 브라우저 네트워크 시간과 분리한다.

전체 raw 행과 성공/실패 수, paired 시간 차이, 중앙값과 범위를 함께 보고한다. 작은 표본에서는 일반 직원 전체의
생산성 개선을 주장하지 않는다. 실제 사람 측정 전에는 개선율을 게시하지 않는다.
