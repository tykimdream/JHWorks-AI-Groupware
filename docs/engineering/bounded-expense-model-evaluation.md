# 실제 경비 모델 평가 — M2-03A/B

2026-10-25 승인된 로컬 실행에서 고정 합성36개를 실제 모델로 평가해 모두 통과했다.
[결과 기록](expense-model-results-2026-10-25.md)은 구조 검사·합성 provider 회귀와 별도로 보관한다.

## 기본 실행: 계획만

```sh
cd apps/api
uv run --frozen python -m app.ops.expense_model_evaluation
```

기본 모드는 설정·키·DB·SDK를 import하지 않는다. 소스 commit·데이터 SHA-256, 필수10개를
먼저 배치한 최대36개 ID, 고정 모델/프롬프트/가격 버전과 상한을 출력한다.
`evaluationKind=model-plan`, 호출 시도0, 모델 정확도 null, 승격 불가다.
파일·원장·클라우드 리소스를 만들지 않는다.

## 검토 후 실행 조건

기존 공개 승인은 AI OFF를 전제로 했다. 이 도구를 추가하거나 PR을 병합한 것만으로
유료 실행·키 업로드·공개 활성화를 승인한 것으로 해석하지 않는다.
실제 실행은 정해진 소스·입력·총 평가 예산의 범위를 별도로 확인한 뒤 진행한다.

```sh
# SOURCE: 계획에 표시된 전체40자 commit. DATASET: 계획의 SHA-256.
# 실제 유료 실행은 승인 뒤에만 사용한다.
uv run --frozen python -m app.ops.expense_model_evaluation --execute \
  --expected-source SOURCE --expected-dataset-sha256 DATASET
```

소스/데이터 해시가 다르거나 관련 AI·core·model·평가·원장·clock·의존성 파일이 HEAD와
달라지면 키를 읽기 전에 거부한다. 실행 도구가 HEAD에 포함되지 않은 경우에도 거부한다.
현재 별도 정리 운영 미커밋 파일은 이 평가의 import·검증 경로에 포함하지 않는다.
명령의 source/hash 비교는 소프트웨어 guard이며 사람의 실제 승인을 대신하지 않는다.

## 고정 실행 상한

| 항목 | 한도/행동 |
| --- | --- |
| 모델 | `gpt-5.4-mini-2026-03-17`, 공식 endpoint·standard tier |
| 사례 | 고정 합성36개 이내, 필수 사례 먼저 |
| 재시도/출력 | SDK retry0, 요청당 최대1600토큰 |
| 이번 실행 비용 | 표준 요금 기준 최대1,000,000micro USD ($1) |
| 같은 원장의 월 비용 | 서울 월 기준 최대1,000,000micro USD ($1) 누적 |
| 동시 실행 | 파일 잠금으로 평가 명령1개, 원장의 provider 슬롯1개 |
| 반복 호출 | 같은 원장/일/범위에서 admission 최대36개 |
| 품질/모델/예산 오류 | 첫 실패에서 중단, 나머지를 성공으로 환산하지 않음 |

각 호출은 [공개 경비와 같은 보수적 예약](public-expense-ai-contract.md)을 거친다.
이전 응답의 보수적 계산 비용에 다음 최대 예약을 더해 실행 예산도 확인한다.
따라서 실행 중 월이 바뀌어도 이번 실행 상한이 월 초기화로 늘어나지 않는다.
실패 후에는 추가 모델을 호출하지 않는다. 불명 청구는 전액, 비정상 usage는 전액·동결로 처리한다.
전체36개 평가가 반드시 예산 안에 완주한다고 보장하지 않는다.

이 예산은 해당 로컬 원장에 기록된 **평가**만 다룬다. 공개 서버 원장·이전 smoke·다른 checkout이나
API 사용은 합산하지 않는다. 원장을 삭제/교체하거나 새 checkout을 쓰면 이 로컬 누적 경계가 깨진다.
원장을 보존하고 같은 파일을 사용해야 하며 provider 계정의 전역 과금 제한을 대체하지 않는다.
요금 변경·세금·환율과 다른 서비스 비용까지 포함한 원화 절대 상한이 아니다.
공개 AI 활성화 예산과 총합은 실행 전에 별도 확인한다.

## 데이터와 결과

실행 모드는 앱의 DB URL을 연결 대상으로 사용하지 않는다. 고정 경로
`artifacts/evals/expense-model-ledger.sqlite3`에 원장2개 테이블만 만든다.
업무 테이블·직원·결재·원격 리소스는 변경하지 않는다. 원장·실행 잠금·결과는 Git 제외 경로다.
원장과 결과는 소유자 전용0600이며 결과는 임시 파일→원자적 교체로 시도 전후 저장한다.
키/SDK 진단/모델 원문을 결과에 넣지 않는다. 입력은 이미 고정된 합성 사례만 사용한다.

`artifacts/evals/expense-model-evaluation.json`에는 다음을 기록한다.

- 평가 source·데이터/프롬프트/가격 버전, case ID·필수 여부, 실제 provider 경계의 시도 수.
- 시도된 사례의 필드/intent 채점, 토큰·지연과 `gradedCount`.
- `fullDatasetCompleted`, `promotionEligible`, 중단 case/errorCode.
- 가격으로 계산한 정상 응답 누적액과 원장의 현재 서울 월·비용·미정산 예약.

부분 실행의 `modelPassRate`는 **채점된 사례만의 비율**이다. 전체36개 정확도가 아니다.
`summary.total`은 계획된 분모를 유지하며 전부 채점/통과하기 전 승격하지 않는다.
모델 report가 passed여도 자동 배포·활성화하지 않는다. 기존 suite도 계획/부분 결과를
실제 전체 성공의 대체 증거로 사용해서는 안 된다.

프로세스 중단 시 마지막 결과는 running이거나 부분 기록일 수 있다. 원장에 남은 예약을 지우거나
자동 환불하지 않는다. 재실행은 같은 원장의 슬롯/예산을 따르며, 필요하면 기존 보수적 복구 절차를
해당 **로컬 원장**에 맞춰 별도 대조해야 한다. 현재 앱 DB용 복구 CLI를 이 파일에 자동 연결하지 않는다.
