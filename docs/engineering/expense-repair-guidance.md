# 경비 확인에서 보완으로 — M3-03

기존 누락·중복 확인 API와 지출 요약을 재사용한다. 누락 이름을 읽은 뒤 사용자가 긴 폼에서 입력칸을 다시 찾아야 하던 문제를 줄인다.

## 실제 동작

- 작성자 자신의 경비 초안 상세에서 누락 항목을 누르면 해당 편집 폼의 입력칸을 화면 중앙으로 이동하고 포커스한다.
- 허용 항목은 지출 금액·실제 지출일·사용처·비용 구분·업무 목적이다. 알 수 없는 항목은 읽기 문구만 표시한다.
- URL에는 고정 field 이름과 기존 목록 scope만 넣는다. 항목 값·반려 의견·업무 본문을 넣지 않는다.
- 링크 클릭과 입력칸 이동은 읽기 전용이다. 사용자가 직접 수정한 뒤 초안 저장해야 서버가 갱신된다.
- 저장 후 기존 상세 확인 API가 새 version에서 다시 실행된다. 변경 전 version 결과는 정상 확인으로 표시하지 않는다.
- 결재자나 제출 후 문서에는 편집 링크를 제공하지 않는다. 서버의 권한·상태·version 검사는 그대로 유지한다.

기존 지출 요약의 금액·날짜·사용처·목적·증빙 참조를 핵심 사실로 사용하며 같은 정보를 별도 요약으로 복제하지 않는다. 중복 제안은 같은 작성자의 날짜·사용처·금액에 대한 후보다. 기존 원문 문서 링크와 조회 권한을 유지하며 중복 확정·자동 제출·자동 반려로 바꾸지 않는다. 영수증 원본 검증은 제공하지 않는다.

## 반려 보완

작성자의 반려 문서·재작성 초안과 편집 화면에서 가장 최근 결재 회차의 반려 의견을 원문 그대로 표시한다. 의견을 업무 내용이나 비용 구분으로 자동 해석해 넣지 않는다. 재작성 전환은 기존 확인 대화상자와 서버 명령을 거치며 과거 이력을 유지한다.

초안 복원 후보가 있으면 항목 포커스보다 사용자의 이어쓰기/지우기 결정을 우선한다. 이미 선택한 보완 항목으로 계속 자동 포커스를 가져가지 않는다.

## 검증과 한계

`e2e/expense-insights.spec.ts`의 PC·모바일 회귀는 실제 누락/중복 API→업무 목적 입력칸 포커스→명시적 저장→다시 확인, 기존 문서 열람, 오류 재시도, 결재자 읽기 전용, 실제 반려→재작성→편집의 의견 유지와 원문 무변경을 검사한다. production CI에도 포함한다.

규칙 기반 확인의 UX 개선이며 새로운 AI 모델 호출이나 사람의 과제 실험 결과는 아니다. 기존 요약을 재사용했고 추가 AI 검토 요약은 구현하지 않았다. 공개 배포는 별도다.
