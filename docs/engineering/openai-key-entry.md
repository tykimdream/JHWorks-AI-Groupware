# 기존 OpenAI 키의 로컬 입력

사용자가 직접 조작하는 터미널에서 저장소 루트 기준 아래 명령을 실행한다.

```sh
python3 tools/store_openai_key.py
```

프롬프트에 키를 붙여넣고 Enter를 누른다. 키를 채팅, 명령 인자, 브라우저 코드, 소스 코드에 넣지 않는다.
입력은 getpass로 숨기고 비대화형 입력이나 숨김 입력 불가 시 중단한다.
저장 대상은 `apps/api/.env`이며 Git의 `.env` 제외 규칙에 포함된다. 새 파일은 0600 권한으로 만들고 기존 파일/심볼릭 링크를 덮어쓰지 않는다. 로컬 파일은 암호화된 금고가 아니므로 OS 사용자 계정의 접근 권한에 의존한다.

이 단계는 키 저장만 한다. 네트워크 호출, GCP Secret/IAM 변경, 유료 AI 활성화는 없다.
`JHWORKS_AI_ENABLED=false`를 함께 기록하므로 기존 설정의 기본값 때문에 자동으로 켜지지 않는다.
키를 확인하려고 파일을 출력하지 않는다. 후속 작업은 존재/권한/키 설정 여부만 검사한다.

클라우드 연결에는 별도 Secret Manager 참조와 최소 권한, 호출 한도, 실제 모델의 품질 확인이 필요하다.
현재 공개 모드는 AI를 비활성화하도록 강제하므로 키 저장을 공개 AI 연결 완료로 표현하지 않는다.

검증: `python3 -m unittest discover -s tools -p 'test_store_openai_key.py'`.
테스트는 가짜 문자열만 사용하며 파일 권한, 덮어쓰기/심볼릭 링크 거부, 파이프/줄바꿈 거부,
숨김 입력 실패 시 중단과 로그 미노출을 확인한다.

[OpenAI 공식 빠른 시작](https://developers.openai.com/api/docs/quickstart)의 서버 환경 변수 기반 키 사용을 따른다.
