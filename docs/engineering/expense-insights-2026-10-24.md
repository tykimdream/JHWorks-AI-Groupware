# 경비 사전 점검·근거 문서 — 2026-10-24

## 결과

문서를 직접 열어 검토를 요청하기 전에 홈에서 지출 정보 누락과 중복 가능성을 먼저 알려준다.
경비 상세에서도 같은 점검을 제공하고 비교할 수 있는 실제 문서로 연결한다.
작성자·지출일·사용처·금액이 같은 다른 경비만 후보로 찾는다. 사용처는 앞뒤 공백만 제거해 비교하며
철자 차이·다른 금액·분할 청구·다른 사람의 지출은 중복 후보로 추정하지 않는다. 같은 사실이어도
정상적인 별도 지출일 수 있어 중복 확정/자동 차단으로 표현하지 않는다.

기존 필수 지출 검증과 목록의 조회 권한/체험 공간 조건을 재사용한다.
결재자는 본인이 열람할 수 없는 같은 작성자의 초안도 근거로 받지 않는다. 근거의 문서 상태도 표시한다.
업무 목적이 비어 있어도 지출일·사용처·양수 금액이 있으면 중복 후보를 함께 확인한다.
자기 자신과 반려 문서는 후보에서 제외한다. 홈은 내 초안/결재 중 문서 최근10개, 근거는 최신3개까지만
표시하며 추가 대상 유무를 반환하고 화면에 점검 범위를 표시한다.

## API와 화면

- GET `/api/v1/approvals/expense-insights`: 홈 점검 결과·점검 수·추가 대상 유무.
- GET `/api/v1/approvals/{id}/expense-checks`: 접근 가능한 경비의 버전·누락 필드·중복 근거·점검 시각.
- 두 경로는 기존 인증·데모 요청 예산·no-store 응답 정책을 유지하며 쓰기나 AI 호출을 하지 않는다.
- 홈/상세 공통 결과 컴포넌트, 요청 취소·문서 버전 대조·오류 시 재시도 제공.
- 점검 실패를 ‘문제 없음’으로 표시하지 않는다. 새 상태/역할에서는 이전 점검을 재사용하지 않는다.

규칙 기반 점검이며 AI 추론을 실행한 것으로 표시하지 않는다. 영수증 원본의 진위·정책 준수·모든 중복을
확정하는 기능도 아니다. 점검은 고정된 문서 수만큼 SQL 조회하며 별도 대용량 성능 개선은 아직 없다.
새 정책·대시보드 저장소·예약·IAM·DB migration·원격 배포는 추가하지 않았다.
