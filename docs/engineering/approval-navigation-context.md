# 결재 목록 탐색 맥락 — M3-02B

## 재현한 문제

목록은 처음 진입할 때만 URL의 `scope`를 읽고, 탭 클릭은 로컬 state만 바꿨다. 상세의 목록 버튼은 항상 `/approvals`로 이동했다. 그래서 결재할 문서를 열고 돌아오면 내가 작성한 문서로 바뀌며 보던 행도 찾기 어려웠다. 탭을 바꾼 뒤 새로고침·뒤로/앞으로 가기도 화면 상태와 일치하지 않았다.

## 동작 계약

| 이동 | 결과 |
| --- | --- |
| 탭 선택 | `/approvals?scope=mine` 또는 `scope=assigned`를 history에 추가 |
| 새로고침·뒤로/앞으로 | URL의 scope로 탭과 API 요청을 결정 |
| 목록→상세 | `?from=mine` 또는 `?from=assigned`만 전달 |
| 상세의 목록 링크 | 원래 scope와 `#approval-문서ID`로 이동 |
| 목록 비동기 응답 후 | 해당 행이 있으면 화면 중앙으로 이동하고 링크에 포커스 |
| 없는 문서·변경된 권한 | 원래 범위의 실제 서버 결과를 표시. 행을 복원하거나 다른 범위를 대신 보여 주지 않음 |
| 직접 상세 진입·알 수 없는 from | 기본 `/approvals`로 복귀 |
| 알 수 없는 scope | 내가 작성한 문서로 조회 |

URL은 문서ID와 고정 scope만 사용하며 제목·본문·직원 정보·외부 복귀 주소를 넣지 않는다. `from`은 알려진 두 값만 허용하고 임의 URL을 이동 대상으로 쓰지 않는다. URL은 권한 증명이 아니며 기존 서버의 작성자·배정·공간 접근 검사를 유지한다.

응답·오류에 scope를 붙여 URL과 다른 범위의 결과를 표시하지 않는다. 탭은 다시 마운트하지 않아 키보드 포커스를 유지한다. 기존 요청은 AbortController로 취소하고 취소된 응답을 무시하므로 늦은 응답이 현재 탭을 덮지 않는다. 명시적인 행 hash가 있을 때만 포커스를 복원하며 일반 목록 진입은 포커스를 가져가지 않는다. 브라우저 기본 뒤로가기의 정확한 픽셀 위치 복원과 상세→편집→저장 왕복의 origin 전달은 이 단위에서 보장하지 않는다.

## 검증과 남은 범위

Playwright의 PC·모바일에서40개 합성 행으로 아래를 확인한다.

- 탭 URL·새로고침·history 뒤로/앞으로와 표시 범위 일치
- 아래쪽 문서 상세·상세 새로고침·복귀 시 scope·포커스·뷰포트 복원
- 알 수 없는 scope/from, 존재하지 않는 행의 안전한 처리
- 기존 늦은 탭 응답 회귀, 실제 홈→AI 초안→저장 흐름

신규 사용자에게 효과를 측정한 결과는 아니며 재현 가능한 탐색 장애를 수정한 구현이다. 입력 중 이동 경고·전체 폼 복원·상세 편집 왕복은 M3-02의 후속 작업이다. 공개 배포·AI 설정·유료 호출은 포함하지 않는다.
