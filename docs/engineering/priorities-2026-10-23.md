사용자 피드백에 따라 **핵심 업무를 실제 화면에서 끝까지 사용할 수 있게 만드는 일**을 먼저 한다.
작성 당시 이 문서를 roadmap 및 기존 실행 계획보다 우선하도록 정했다. 현재 순서는 상단의 최신 로드맵을 따른다. 기존 Phase 1~11 구현과 검증을 재사용하며,
이미 구현된 기능을 미구현으로 간주하거나 처음부터 다시 만들지 않는다.

## 실행 순서

| 순서 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1 | 결재·휴가 핵심 흐름 완결과 차단 결함 수정 | 실제 화면에서 작성→저장→제출→결재자 승인/반려→결과 확인. 휴가 잔여·예약·사용 일수가 상태와 일치하고 반려 후 수정·재상신 가능 |
| 2 | AI 휴가 상담·결재 초안의 대표 시나리오 완성 | 자연어 요청→일정/연차 근거가 있는 후보→선택→초안 미리보기→명시적 저장. 제출은 별도 확인, AI 실패 시 직접 작성 가능 |
| 3 | 대표 화면의 사용성·응답 정확성 개선 | 결재 목록 탭 응답 경합 수정, 로딩·빈 결과·오류·재시도 구분, 목록/상세/작성/휴가 화면의 모바일·키보드 기본 사용 가능 |
| 4 | 방문자 체험 완결 | 체험 진입→역할 전환→업무 완료→피드백. 두 방문자 격리와 만료·요청 한도 도달 시 안내·복구를 실제 화면에서 확인 |
| 5 | 공개에 필요한 최소 운영 마감 | 이미 확인한 세션·데이터 경계 증거 재사용. 제한된 유입에서 데이터 누적 상한·정리 담당/주기·실패 시 중단/수동 복구 경로 확보. 남은 정리/알림 검증만 제한된 범위로 재개 |
| 6 | 실제 앱 공개와 포트폴리오 연결 | 실제 도메인에서 쿠키·캐시·접근 경계와 대표 흐름 확인, 문제 시 준비 화면 복귀 가능. 포트폴리오에서 체험·의견까지 연결 |
| 7 | 공개 후 피드백으로 제품 개선 | 반복되는 사용 장애부터 수정하고 대표 화면의 개선 전후와 사용자 근거 기록 |
| 8 | 측정에 따른 성능·운영 확장 | 필요한 목록 페이지네이션, PG 경합·장애 보강, 자동 배포·백업 개선을 실제 병목과 운영 필요 순으로 수행 |
| 9 | 선택 확장 | 공개 유료 AI 연결, 추가 대시보드·조직 관리 등은 핵심 흐름과 수요 확인 후 별도 범위 결정 |

1~4는 지금 진행할 제품 작업이다. 5~6은 공개 직전 수행하며, 7~9는 이후다.
실제 권한 침해·데이터 손상 결함이 발견되면 해당 결함을 우선 해결한다.
AI 대표 흐름은 로컬/비공개 환경에서 검증할 수 있으며, 공개 유료 AI 활성화가 선행 조건은 아니다.
fake AI로 확인한 화면·계약 검증과 실제 모델의 품질 평가는 구분해 기록한다.

이후 기존 작성·제출·승인/반려·휴가 화면을 직접 조작해 실제로 막히는 부분만 작은 변경으로 해결한다.
전체 재진단이나 운영 관찰 대기를 이 작업의 선행 조건으로 두지 않는다.

## 정리·알림 작업의 처리

운영 보강은 유효한 작업이지만 현재 제품 개발을 앞설 우선순위는 아니다.
기존 코드·설정·증거를 보존하고 추가 원격 실행 및 장시간 관찰은 지금 중단한다.
Scheduler는 마지막 확인 시 PAUSED였다. 복구 실행의 최종 결과 등 미확인 항목은 완료로 표시하지 않으며,
공개 준비 때 기존 실행 결과를 읽어 확인한 뒤 필요한 검증만 재개한다. 동일 실행을 무작정 반복하지 않는다.
자동 삭제 활성화·새 권한/비용·공개 노출은 기존 승인 범위를 확인해 처리한다.
상시 공개 시에는 데이터 누적을 제한할 정리 운영이 필요하지만, 실패/누락 알림의 장시간 관찰이
비공개 핵심 기능 개발을 막는 조건은 아니다.
