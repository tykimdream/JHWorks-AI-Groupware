# 처음 사용하는 사람을 위한 경비 업무 안내

2026-10-26 · PR #104의 후속 구현. 공개 배포는 별도다.

## 사용자 문제와 선택

사용자가 제안한 CRM 단계 안내처럼, 처음 쓰는 사람은 상태 이름만으로 필수값·전제조건·다음 행동을 알기 어렵다. 현재 프로젝트의 실제 도메인인 경비 작성·반려 보완·결재 검토에 먼저 적용한다. CRM은 미구현 도메인이므로 지원한다고 표시하지 않는다.

| 대안 | 선택과 이유 |
| --- | --- |
| 자유 입력 챗봇 | 첫 버전은 선택형 Q&A로 범위를 좁혔다. 저장/제출·증빙·반려·결재자 질문은 결정적인 업무 계약으로 답할 수 있다. 새로운 유료 모델 호출과 안내 환각을 추가할 이유가 없다. 자유 질문은 향후 근거 검색·응답 평가를 갖춘 별도 기능으로 검토한다. |
| 자동 팝업·캐릭터 위저드 | 사용자가 필요할 때 여는 도움말 버튼을 선택했다. 작성 중 입력과 맥락을 보존하고 강제로 단계를 진행시키지 않는다. 기존 첫 방문 가이드를 교체하거나 반복 노출하지 않는다. |
| 항상 펼친 스티키 바 | 좁은 화면과 긴 양식에서 공간을 차지하므로 닫을 수 있는 우측 모달 패널을 선택했다. 모바일은 전체 폭, PC는 제한 폭이며 원래 화면이 뒤에 남는다. 열려 있는 동안 배경 입력은 잠그고 닫으면 원래 버튼으로 포커스를 돌린다. |
| 프론트엔드에 필수값 목록 복제 | 경비 제출 검사와 안내가 같은 `EXPENSE_REQUIRED_FIELDS`를 사용한다. 서버가 안내 metadata를 제공하고 기존 expense-checks의 필드 검사 결과를 재사용한다. 문구·단계 설명은 서버 상태 전이 계약에 맞춘 수기 콘텐츠이므로 규칙 변경 시 동반 리뷰가 필요하다. |
| 입력이 있으면 제출 가능 표시 | 저장된 문서 버전의 경비 필드만 검사한다. 제목·업무 내용·관리자·권한·동시 변경·규정 전체 검사를 대체하지 않는다. 새 문서/저장하지 않은 수정은 검증하지 않았다고 명시한다. |

## 기능과 디자인

- 경비 작성 폼과 상세 화면에서 `경비 업무 도움말` 버튼으로 연다. 자동으로 열거나 입력을 수정·저장·제출하지 않는다.
- 현재 상태의 의미·다음 단계, 4개 선택형 질문, 경비 필드 기준·합성 예시, 다른 단계 설명과 출처 버전을 제공한다. 승인 완료를 송금 완료로 설명하지 않는다.
- 작성 폼에서는 입력으로 이동할 수 있다. 도움말을 닫고 해당 필드에 포커스를 옮기며 값은 그대로 유지한다.
- 기존 JHW의 흰 표면·보라 강조·회색 텍스트·테두리·타이포 토큰과 Tailwind를 사용한다. 과한 장식이나 독립된 챗봇 캐릭터는 추가하지 않는다. 상태 설명 → 질문/답변 → 필요한 필드 순서로 배치해 설명 목록에 질문이 묻히지 않게 한다.
- native dialog의 모달 동작·키보드 순환·Escape를 사용한다. 제목과 닫기 버튼을 고정하고 내용만 스크롤한다. 요청은 AbortController로 종료하며 실패와 다시 조회를 제공한다.
- 도움말을 닫았다 다시 열면 현재 서버 안내를 다시 조회한다. 대화 기록이나 실제 업무 입력을 추가 보관하지 않는다.

## 서버 경계

`GET /approvals/expense-guide`는 로그인한 사용자에게 `expense-guide-v1` 안내를 반환한다. 모델·DB 쓰기·방문자 쓰기 예산 소비가 없다. 공개 AI OFF에서도 사용할 수 있다. 새 경로는 `/{approval_id}`보다 먼저 선언해 문서 ID로 오인하지 않는다.

저장본 점검은 기존 `GET /approvals/{id}/expense-checks`를 사용해 작성자/지정 결재자·방문 공간 열람 경계를 유지한다. 요청한 문서 버전과 다르면 결과를 표시하지 않고 새로고침을 안내한다. 작성 화면에서는 마지막 저장본을 점검한다는 한계를 명시하며, 새 양식의 현재 입력은 서버로 전송하지 않는다. 영수증 원본 진위와 전체 규정 준수를 인증하지 않는다. 단계 안내만으로 실제 행동 권한이 생기지 않으며 명령 API가 최종 조건을 검사한다.

## 검증

전체 API·정적 검사와 함께 인증·필수값 계약 대응·무변경 API 검사를 추가했다. 브라우저에서는 입력 유지·쓰기 없음·질문 답변·Escape/포커스 복귀·포커스 순환·필드 이동·저장본 누락·버전 불일치·실패 재조회·접근성을 확인한다. 공개 모드의 AI OFF 도움말과 Swagger 스키마 표시도 확인한다. 실제 신규 사용자 학습 시간이나 완료율은 측정 전이다.

## 로컬 검증 기록

API **636개 통과·34개 제외**, mypy **210개 파일 통과**, ruff·web lint/type·production build 통과. production PC/모바일 **8개**(도움말 6개 + 기존 반려 수정 2개)를 통과했다. 공개 AI OFF 모드의 도움말과 Swagger 검사를 별도로 실행한다. 첫 공개 모드 검사에서 React Strict Mode의 effect 재실행 중 dialog cleanup이 close 이벤트를 발생시켜 새 패널을 닫는 결함을 발견했다. DOM 제거에 닫기를 맡기고 이미 열린 dialog는 다시 열지 않도록 수정해 개발·production을 함께 확인한다.

사용자에게 보이는 안내는 AI 응답으로 표시하지 않는다. 실제 사용자 학습 효과는 측정 전이고 CRM 안내·자유 질문·실시간 미저장 필드 진단은 구현 범위 밖이다.

Strict Mode 수정 후 공개 AI OFF의 PC/모바일 도움말·Swagger **4개 통과**, 최종 production 도움말 PC/모바일 **6개 통과**. 이전 반려 수정 PC/모바일 2개도 통과했다. [PC 화면](../portfolio/prototype/expense-guide-desktop.png) · [모바일 화면](../portfolio/prototype/expense-guide-mobile.png)은 합성 데이터의 실제 웹/API 연결 화면이며 외부 AI 호출은 없다.
