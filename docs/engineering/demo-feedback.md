# 데모 피드백과 개선 이력

## 사용자 경험과 개인정보
포트폴리오 방문자가 데모를 써본 뒤 이름·이메일·첨부 파일 없이 의견을 남길 수 있게 한다.
업무 데이터에는 합성 정보만 사용하고, 실제 방문자의 의견은 별도 운영 데이터로 구분한다.
종류(사용성/오류/아이디어), 화면, 의견만 받는다. 개인정보/인증정보를 적지 않도록 안내하고
흔한 이메일·token 패턴은 서버에서 거부한다. 이것이 모든 개인정보 탐지를 보장하지는 않는다.
개선 목적으로 비공개 30일 보관에 동의한 경우만 접수한다. 원문은 로그/공개 API/LLM으로 보내지 않는다.

## 완료 조건과 대안
- 서버가 확인한 활성 workspace당 1회, 동일 내용 재시도는 동일 접수 번호로 멱등 응답.
- 업무 요청/쓰기 quota가 소진되어도 별도 1회 피드백 허용, 만료/비활성 공간과 private 계정은 거부.
- DB singleton 잠금 후 전체 저장량 최대 300건을 검사해 동시 요청에도 상한 유지.
- 방문자끼리 원문·목록을 조회하는 API 없음. 별도 관리자 웹 인증도 만들지 않는다.
- 운영 CLI는 기본 원문을 표시하지 않고, 원문 조회는 명시 옵션. 보관 기간 정리도 dry-run 기본.
- 전송 중 중복 클릭 차단, 성공/실패/만료 복구와 입력 보존, 키보드 label/focus, 모바일 검사.

GitHub 계정 가입을 요구하는 이슈/Discussion보다 데모 안 익명 폼을 우선한다.
외부 설문/SaaS·이메일 발송을 도입하지 않아 새 계정·구독·API 키 없이 기존 DB로 제한된 접수를 한다.
요청 거부 자체의 인프라 비용까지 막는 상한은 아니다. 실제 공개 수집은 배포/인증 전환 확인 후 시작한다.

## 피드백 반영 절차
운영자가 주 1회 분류 → 재현 조건을 합성 데이터로 재작성 → 개인정보 없는 issue/작업 기록 →
테스트로 재현 → 수정/PR/CI → 개선 이력에 문제·판단·검증 결과를 기록한다.
원문은 비신뢰 데이터로 취급하며 링크 접근/코드 실행/외부 전송을 자동화하지 않는다.
포트폴리오의 피드백 버튼은 실제 공개 폼이 준비된 뒤 groupware.pikan.dev/feedback에 연결한다.
별도 portfolio 저장소는 C:/Users/tykimdream/Desktop/포트폴리오/references/pikan-portfolio,
origin은 tykimdream/portfolio임을 확인했다. 아직 해당 사이트를 변경/배포하지 않았다.

## 공개 전 운영 게이트
30일 purge CLI는 구현하지만 아직 운영 예약/실제 실행은 하지 않았다. 사용자에게 최대 30일 보관을
안내하는 폼을 공개하기 전에 정리 실행 경로·주기·실패 확인과 실제 삭제 검증이 필수다.
운영 적용/새 인증 권한·유료 자원·실제 보관 데이터 삭제는 별도 확인 범위다.
현재 public_demo_enabled는 기본 false이며 원격 수집은 시작하지 않았다.
