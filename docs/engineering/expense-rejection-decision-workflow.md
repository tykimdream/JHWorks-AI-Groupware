# 반려 경비 수정과 결재자 검토

기준: 2026-10-26 · 소스 구현/합성 검증. 공개 배포·실제 모델 평가는 별도다.

## 문제와 목표

초안 생성만으로는 정산 업무가 끝나지 않는다. 작성자는 반려 의견을 읽고 어떤 사실을 보완할지 결정해야 하고, 결재자는 문서·증빙 참조·규정·이전 의견을 오가며 확인해야 한다. 사용자가 모든 AI 오류를 찾아내도록 맡기는 대신, 기존 필드 대조·규정 검사를 수정 과정에도 적용한다.

이번 과제는 ‘모든 반려를 자동 해결’이 아니다. 실제 사실이 더 필요한 경우 질문하고, 변경 전후를 확인한 뒤 같은 문서의 초안으로 반영하며, 결재자는 결정에 필요한 근거를 한곳에서 읽을 수 있게 한다.

## 검토한 대안과 선택

| 결정 | 검토한 대안 | 선택 이유와 대가 |
| --- | --- | --- |
| 수정 제안 생성 | 기존 문서 전체를 자유 재작성 / 새 초안 문서 생성 / 기존 경비 필드와 추가 사실로 제안 | 기존 실행 하네스를 재사용한다. 원문 대응·규정 검사를 우회하지 않고 같은 문서를 유지한다. 자유로운 문장 교정 범위는 좁다. |
| 반려 의견의 역할 | 의견을 지출 사실에 합치기 / 별도의 수정 요청 context로 전달 | ‘금액을 바꿔라’는 의견이 실제 지출 증거가 될 수 없다. 모델에는 JSON의 별도 user data로 전달하고 grounding의 request/answers에서는 제외한다. 의견의 사실을 적용하려면 작성자가 추가 사실로 제공해야 한다. |
| 저장 방식 | 생성 즉시 덮어쓰기 / revise 호출 후 PATCH 두 번 / 확인한 제안의 원자적 반영 | 별도 만료 서명에 작성자·문서 ID·버전·preview hash·정책 fingerprint를 결합한다. 한 트랜잭션에서 REJECTED→DRAFT와 필드 갱신을 처리하고 기존 결재 이력을 유지한다. 제출은 별도다. |
| 응답 유실 후 재시도 | 자동 재시도 / 서버 상태 재조회 | 이번 수정 적용은 멱등 replay API가 아니다. 첫 성공 이후 재요청은 버전/상태 충돌이다. UI는 실패 시 제안을 제거하고 재전송을 차단하며 새로고침으로 저장 여부 확인을 안내한다. |
| 결재자 요약 | 추가 LLM 요약·점수 / 서버 데이터와 규정 기준의 근거 모음 | 결정적인 값과 현재 원문을 보여주는 데 모델 호출은 필요하지 않다. 조회 가능한 중복 후보·미판정 규칙·영수증 미검증을 명시하고 승인 추천/전체 준수 점수를 만들지 않는다. |
| 반려 해결 판정 | 이전 의견이 있으면 해결 완료 표시 / 현재 문서와 의견을 함께 표시 | 이전 회차 원문 snapshot이 없어 완전한 전후 비교를 입증할 수 없다. 현재 제안 적용 직전 diff는 제공하지만, 과거 제출본과의 비교나 모든 사유 해결을 주장하지 않는다. |
| 프레임워크 | 별도 에이전트 그래프 추가 / 단일 제안 실행 재사용 | 현재 흐름은 모델 1회와 명시적 확인이다. 재개 가능한 다단계 그래프가 필요하다는 근거가 없어 새 의존성을 추가하지 않는다. |

[OpenAI Structured Outputs 문서](https://developers.openai.com/api/docs/guides/structured-outputs)가 설명하는 출력 형식 제약은 내용의 진실성을 보장하지 않는다. 따라서 구조화 응답 이후의 원문 대응과 서명·버전 검사를 유지한다. 반려 context에는 별도 `expense-revision-v1` 지침과 prompt cache key를 사용하며, 기존 일반 초안 v5 입력에는 context 필드를 추가 전송하지 않는다.

## 구현 계약

- `POST /approvals/{id}/expense-revision/prepare`: 작성자의 REJECTED EXPENSE만 허용한다. 기존 구조화 필드를 표준 라벨로 직렬화하고 추가 답변과 함께 하네스로 보낸다. 반려 원문은 별도 context이며 DB/문서를 변경하지 않는다. 일반 신규 문서 생성용 확인 토큰은 발급하지 않는다.
- 원문 사실이 아닌 제목·자유 본문을 지출 근거로 재사용하지 않는다. 원래 구조화 필드는 작성자가 저장한 사실이지, 과거 AI grounding이 검증됐다는 증명은 아니다.
- 기존 값에 여러 줄/필드 구분 기호가 있으면 직렬화 의미가 뒤섞이지 않도록 직접 편집으로 안내한다. 지원 범위 밖 표현을 조용히 변환하지 않는다.
- 모델이 다른 문서 유형을 제안하면 거절한다. grounding에서 값이 대조되지 않으면 질문으로 전환하고 적용 토큰을 만들지 않는다. AI가 어떤 보완을 제안할지는 실제 모델 평가가 별도로 필요하다.
- 추가 질문은 입력한 사실만 보존해 다시 실행하며 숨은 자동 재시도·다중 모델 심판을 추가하지 않는다. 제안 실행마다 기존 호출 제한과 provider timeout 경계를 따른다.
- `POST /approvals/{id}/expense-revision/apply`: 작성자·버전·서명·현재 정책을 확인하고, 행 잠금 이후 상태/버전을 다시 확인한다. 문서 ID·첨부 메타데이터·과거 결재 의견은 보존한다. 수정 전후에는 제목·본문과 변경된 경비 필드를 모두 표시한다.
- 정책 fingerprint는 요청 간 변경 검사이며 정책 발행과 수정 적용의 전역 직렬화를 보장하지 않는다. 성공한 적용을 되돌리는 별도 undo 기능은 없다. 초안의 일반 편집으로 다시 수정할 수 있다.
- `GET /approvals/{id}/decision-brief?version=N`: 현재 PENDING 단계의 담당 결재자만 조회한다. 작성자·과거 결재자에게 승인 역할을 넓히지 않는다. 기존 workspace 열람 경계를 재사용한다. 모델·임베딩 호출 없이 활성 규정 원문 catalog와 조회 가능한 중복 후보를 반환한다.
- 제안 API는 공개 데모에서 서버가 차단한다. UI도 공개/AI OFF에서 직접 수정 경로를 안내한다. 공개 경비 AI의 기존 좁은 capability를 확대하지 않는다. 결재자 근거 조회는 AI OFF에서도 동작한다.

## 화면 선택

기존 JHW 색상·타이포·테두리·간격 토큰을 유지하고 Tailwind로 구성한다. 반려 작성자의 작업은 ‘실제 사실 입력 → 변경 전후 → 같은 문서의 초안에 반영’으로 배치하고 상세 필드·규정 검사는 펼쳐 보게 한다. PC는 변경 전/제안을 나란히, 모바일은 위아래로 표시한다. 결재자는 문서 앞에서 금액·미확인 증빙·규정 기준을 읽고 아래 원문과 결재 의견으로 이어간다. PC에서는 필수 정보와 규정 기준을 두 열로 배치하고, 추가 확인 규칙을 먼저 표시한다. 기존 중복 확인 패널은 현재 결재자 화면에서 중복 표시하지 않는다. 장식용 점수·승인 추천 배지는 두지 않는다.

## 검증과 남은 한계

실제 모델·키·클라우드·마이그레이션 없이 합성 provider와 실제 API로 검증한다. 테스트 개수는 사용자 효과나 AI 정확도가 아니다. 기존 v4 36개 실제 모델 평가와 v5/v1 수정 prompt의 결과를 혼합하지 않는다.

핵심 회귀: 제안 준비의 무변경, 원문에 없는 반려 금액 차단, 다른 intent 차단, 작성자·버전·정책/preview 변조 방어, 처리 중 문서 변경, 같은 문서 초안 반영과 이력 유지·자동 제출 없음, 현재 결재자 전용 근거 조회. PC·모바일 전체 수정/재제출 및 접근성 검사를 추가한다.

다음 검증: 별도 승인된 제한 예산으로 실제 반려 의견·추가 질문·모호한 목적의 모델 제안 품질 평가, 사용자 과제 관찰, 필요가 확인되면 과거 제출본 snapshot과 변경 내역 보존. 영수증 파일·OCR·진위 판정은 아직 범위 밖이다.

## 최종 로컬 검증 기록

후속 UX 후보로 사용자가 제안한 ‘업무 안내 패널’을 보관한다. 현재 단계의 의미·필수값·전제조건·예시를 우측 패널(모바일에서는 닫을 수 있는 시트)로 보여주고, 선택형 질문부터 제공한다. 첫 적용 대상은 경비 작성·반려 보완·결재 검토이며 CRM은 현재 구현 도메인이 아니므로 확장 예시로만 다룬다. 안내 출처는 서버 규칙/버전과 연결하고 자유 질문은 추후 별도 검증한다. 자동 팝업·무단 입력 변경 없이 필요할 때 열도록 한다. 이번 PR에는 패널을 구현하지 않는다.

API **634개 통과·34개 제외**, mypy **207개 파일 통과**, ruff와 web lint/type·production build 통과. production PC/모바일 **10개 통과**(새 반려/재제출 흐름 2개 + 기존 경비 2개 + 검증 UI 6개), 새 화면 자동 접근성 검사 포함. 소스/지침 변경 뒤 실제 모델은 호출하지 않았다.

전체 CI가 기존 결재자 테스트의 옛 패널 기대를 발견했다. 대체한 검토 요약의 규정 확인 필요·증빙 미검증 표시와 읽기 전용 계약을 검사하도록 수정했다. 별도로 기존 경비 점검·직접 재작성과 새 AI 수정 흐름을 묶은 production PC/모바일 8개를 통과했다. 테스트를 제거하거나 기존 반려 이력·본문 유지 검사를 완화하지 않았다.
