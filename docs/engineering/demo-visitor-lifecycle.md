# 방문자 생성·공개 전용 모드·수명 관리

## 범위와 완료 조건
workspace 기반(PR #41, main 0938136)은 CI 5개/자체 리뷰 후 병합됐다. 실제 외부 staging은 9a29f2e이며
이번 구현을 아직 배포하지 않는다. 다음은 비밀번호 없는 방문자 시작/역할 체험과 보관 상한이다.
public_demo_enabled 기본 false. true일 때 비공개 일반 계정의 세션/비밀번호 로그인을 거부하고
AI는 설정 검증으로 끈다. 새 endpoint를 외부에 노출하거나 새 인증정보를 발급하는 운영 적용 전에는 확인받는다.

- DB 고정 UTC 일별 기본 20회 생성, 보관 workspace 최대 30개(만료된 행 포함).
- 생성 예산 singleton 행을 같은 transaction에서 잠그고 직원·부서·연차를 함께 생성.
- 공간 수명 15분·쓰기 20회, 전체 보호 요청 100회. 시간·할당은 서버가 정하고 DB에서 검증.
- 기존 활성 공간에서 다시 시작하면 공간을 재사용한다. quota/용량 거부는 429, DB 실패는 503.
- 본인 공간에서만 작성자/결재자 전환. 새 개인 비밀번호/credential은 저장하지 않는다.
- 만료 24시간 뒤 정리할 수 있는 dry-run 기본 운영 도구. 실제 삭제는 별도 확인 후에만 실행.
- 잘못된 다른 공간/일반 계정 참조를 발견하면 삭제를 거부하고 기존 private 데이터를 보존.
- 로컬/전용 loopback PostgreSQL 경합·정리·기존 회귀를 구분한다.

## 비용과 선택
Redis/별도 인증 제공자 없이 기존 PostgreSQL의 원자 조건부 갱신과 JWT를 재사용한다.
전체 요청 예산은 업무/AI 입력 처리량을 제한하지만 인증 전 요청·429 자체의 DB/Cloud Run 비용까지
차단하지 않는다. min=0/max instance, 생성/보관 상한, AI 꺼짐과 모니터링을 함께 사용한다.
cleanup을 예약/실행하지 않으면 보관 상한에서 새 체험이 중단되는 fail-closed 방식이다.
실제 보관 삭제/공개 IAM/새 자원/AI 연결은 이 코드 작업의 승인이 아니다.
피드백은 업무 데이터 정리와 분리해 짧은 익명 의견만 보관하는 다음 독립 작업으로 구현한다.

## 검증 이력
- 기존 workspace/마이그레이션과 새 lifecycle 관련 27개 통과. 최초 전체 2 failed/367 passed는
  새 테스트의 settings cache 초기화로 기존 middleware와 설정 객체가 분리된 fixture 문제였다.
  같은 cached 객체를 monkeypatch하도록 고쳤고 CSRF 구현은 변경하지 않았다.
- 수정 후 전체 369개 통과/16 skip을 확인했고, 생성 도중 DB 오류 rollback과 날짜 역행 차단을 추가했다.
- Ruff 및 strict mypy 138 files 통과. 최종 전체 및 PostgreSQL/브라우저/컨테이너 결과는 해당 PR checks로 확인한다.
- 실제 외부 계정 생성·공개 인증 전환·DB migration·데이터 삭제는 실행하지 않았다.
