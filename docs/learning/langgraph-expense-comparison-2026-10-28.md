# 경비 미리보기 LangGraph 실험 — 2026-10-28

## 범위

[실험 코드](../../apps/api/experiments/expense_graph.py)는 기존 `prepare_approval_draft`를
그대로 호출한다. `prepare → 부족하면 ask → 답변 후 prepare → 미리보기`를 그래프로
묶고, 사용자 확인 토큰은 만들지 않는다. API 라우트·라이브 데모·제품 의존성은
변경하지 않았다. 호출 예산 가드와 인증 경계 바깥의 **합성 데이터 전용 실험**이므로
실제 모델이나 실제 사용자 요청을 연결하면 안 된다. 업무 저장·상신 도구도 없다.

## 직접 실행

```sh
cd apps/api
uv run --no-env-file --with langgraph==1.2.17 --with langgraph-checkpoint-sqlite==3.1.2 pytest experiments/tests/test_expense_graph.py -q
uv run ruff check experiments
```

테스트에서는 tracing을 끄고, 합성 직원·합성 DB·가짜 모델과 임시 SQLite checkpoint를
사용한다. 외부 모델 호출은 없다. 패키지가 없으면 `uv`가 다운로드한다. 테스트 결과:
**5개 통과** (2026-10-28).

## 같은 시나리오 비교

요청: “코엑스 전시회 출장 교통비 38,000원 정산해줘.” 사용처와 지출일이 빠지면
질문하고, 합성 답변을 추가해 미리보기를 만든다. 두 방식에 같은 가짜 모델 응답과
기존 서비스 검증을 제공하여 응답의 status·질문·누락 필드·후보·미리보기·입력 근거·
규정 검사 결과를 비교했다. 생성 시간과 실행 ID 같은 실행별 값은 비교에서 제외한다.

| 항목 | 기존 직접 호출 | LangGraph 실험 |
| --- | --- | --- |
| 추가 질문 후 재개 | 원문과 답변을 함께 다시 전달 | checkpoint에서 답변을 받아 같은 서비스 재호출; 연결을 닫고 새 그래프로 재개 확인 |
| 동일 응답 계약 | 질문 후 PREVIEW | 비교한 응답 필드 동일 |
| 모의 모델 성공 호출 | 2회 | 2회. 재개 자체가 호출을 줄이지 않음 |
| 실제 토큰·비용 | 실제 모델 호출 없음, 측정 불가 | 실제 모델 호출 없음, 측정 불가 |
| 실패 복구 | 기존 방식은 호출자가 요청과 답변을 다시 전달 | 답변 후 공급자 실패를 고친 뒤 같은 checkpoint에서 준비 단계 재시도 확인 |
| 잘못된 답변 | 호출 전 입력 검증 필요 | 빈 답변이면 재질문; 모델 재호출 없음 |
| 취소·업무 저장 | 이번 비교에서 확인 토큰 없이 저장 없음 | 취소 시 모델 재호출과 업무 저장 없음 |
| 코드 이해·테스트 | 기존 서비스와 요청/응답만 추적 | 그래프 단계가 보이지만 checkpoint·중단 노드 재실행·오류 복구까지 알아야 함 |

호출 수는 위 단일 성공 시나리오의 **가짜 provider 호출**이다. 실패한 호출은 이 가짜의
성공 입력 목록에 기록되지 않으므로 재시도 비용을 측정한 결과가 아니다. 실제 모델의
추출 품질, 토큰, 금액, 지연은 측정하지 않았다. 기존 서비스 자체도 규정 조회와 같은
다른 provider를 호출할 수 있어 전체 비용을 이 숫자로 추정할 수 없다.

테스트 중 빈 답변에서 예외를 발생시키면 재개할 때 이전 잘못된 답변이 다시 재생되어
같은 오류에 머무는 현상을 확인했다. 실험에서는 오류를 표시하고 다시 `interrupt`하여
올바른 답변을 받는다. 답변이 8개에 도달하면 기존 요청 스키마의 제한에 맞춰 중단한다.
실패 후 재시도는 자동이 아니라 테스트에서 명시적으로 실행했다.

## 코드 읽는 순서

1. `ExpenseState`: 원문·답변·결과 등 실험의 진행 상태다.
2. `prepare`: 기존 서비스가 입력 근거와 규정을 확인한 결과를 상태에 넣는다.
3. `ask`: 질문을 `interrupt`로 반환하고 답변이 도착할 때까지 멈춘다.
4. 조건부 연결: 추가 정보가 필요하면 질문으로, 준비되거나 지원하지 않으면 종료한다.
5. `Command(resume=...)`: 같은 실험 thread의 답변을 전달한다. 재개 시 `ask` 앞부분이
   다시 실행되므로 그 안에서 외부 호출이나 업무 저장을 하지 않는다.

## 판단과 한계

LangGraph가 질문·재개 지점을 명시하고, 답변 후 오류에서 진행 상태를 보존하는 모습을
확인했다. 반면 현재는 기존 서비스를 감싸는 구조라 성공 시 모델 호출은 줄지 않았고,
별도 저장소와 잘못된 입력의 재개 처리가 추가됐다. **제품 도입의 우위는 아직 입증되지
않았다.** 기존 경비·휴가 서비스와 라이브 데모는 그대로 둔다.

임시 SQLite 연결을 다시 열었을 뿐 프로세스 강제 종료·운영 PostgreSQL·다중 사용자
소유권·만료·동시 재개·실제 모델 호출이나 비용은 검증하지 않았다. checkpoint에는 합성
원문과 답변이 포함된다. 제품 적용 전에는 데이터 최소화·보존/삭제·사용자별 접근 제어,
호출 예산과 재시도, 업무 DB와의 관계를 별도로 구현하고 검증해야 한다.
