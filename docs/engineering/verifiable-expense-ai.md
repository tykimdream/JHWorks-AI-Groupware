# 검증 가능한 경비 AI — 실행 계획

2026-10-26 사용자 요청으로 다음 제품 미션을 ‘제한 공개 준비’에서 **서버가 검증하는 경비 AI**로 변경한다. 이 문서가 로드맵의 다음 AI 작업 순서를 대체한다. 공개 AI는 OFF이며 유료 실행·원격 키/DB 적용은 이번 구현과 구분한다.

## 제품 책임

사용자는 실제 지출 사실과 업무 의사결정을 확인한다. 시스템은 응답 구조·원문 근거·정책 출처·권한·금액/날짜·상태 전이를 검사한다. 사용자 확인 버튼이나 신규 사용자 실험으로 시스템 검증 책임을 대체하지 않는다.

각 단계는 리뷰·필수 CI 통과 후 병합한다. 모델을 심판으로 한 번 더 부르는 것을 검증의 기본으로 삼지 않는다. 현재 한 번의 provider 호출과 서버 결정 구조는 별도 그래프 프레임워크 없이 구현하고, 실제 재개/분기가 복잡해질 때 LangGraph 적용을 검토한다.

## V1 범위와 한계

하네스는 `input → provider → normalize → validate → policy → preview`를 관리한다. validate는 기존 필수값·형식·날짜·비용 일관성 검사를 뜻하며, 원문 사실의 진위 검증이 아니다. policy는 현재 검색 상태를 기록할 뿐 법적/업무적 적합성을 인증하지 않는다. 공개 경로의 정책 조회 불가는 그대로 유지한다.

각 prepare는 독립 실행 ID를 만들고 보완 요청은 새 실행이다. 모델 숨은 재시도/토큰 과금은 provider·비용 원장 책임이며 하네스의 provider 단계 진입 횟수와 구분한다. 실패 시 후속 단계와 저장 토큰 발급을 실행하지 않는다. 기록에는 요청/응답 원문·직원/공간 ID·확인 토큰·예외 문구를 넣지 않는다. 실행 ID는 추적용이며 인증/재개 토큰이 아니다. 지속 저장·GET run·자동 재시도·재개 기능은 V1 범위가 아니다.

## V1 구현·검증 기록

기존 `/approval-draft-assistant/prepare`가 실제 하네스를 사용한다. 성공 응답의 `execution`과 실패 응답의 `error.details.execution`에 실행 ID·고정 하네스/프롬프트 버전·허용 형식의 provider/model 식별자·단계 결과·서버 단조 시계 기준 시간을 반환한다. 기존 HTTP 오류 코드와 provider 비용 예약·정산은 유지한다. HTTP body 검증/인증/기능 gate는 prepare 진입 전 기존 경계이며 별도 실행 trace를 만들지 않는다.

빈 공백 요청은 provider 호출 전 거절하고, provider가 schema를 우회한 candidate를 반환해도 정규화 단계에서 재검사한다. 누락 정보와 미지원 요청은 policy/preview를 수행하지 않으며, policy 검색의 UNAVAILABLE/NOT_INDEXED를 PASSED로 기록하지 않는다. 조회 결과가 READY여도 정책 준수/인용 진위를 인증한 뜻은 아니다. 성공 응답 조립이 끝난 뒤에만 실행을 성공 종료한다. stage 시간은 하네스 내부 벽시계 시간으로 기존 provider latency와 구분한다.

로컬 API 전체 회귀 **604개 통과·34개 제외**, mypy **196개 파일 통과**. PostgreSQL 전용 검사는 CI에서 별도로 확인한다. 성공·보완·미지원·확인 저장·idempotency 기존 회귀와 새 단계 순서/실패 중단·안전한 오류·로그 원문 배제·빈 입력·스키마 우회 방어를 확인했다. 새 실제 모델 호출·원격 적용·AI 공개는 하지 않았다. 이는 V1 시점의 기록이며 V2 이후 구현은 아래에 별도로 기록한다.

## V2 입력 대응 검증

현재 검사는 추출값과 사용자가 제공한 텍스트의 **대응**을 확인한다. 원문 의미 전체의 함의·실제 지출·영수증 원본 진위를 판정하는 엔진이 아니다. [OpenAI Structured Outputs 공식 문서](https://developers.openai.com/api/docs/guides/structured-outputs)는 형식에 맞는 출력에도 내용 오류가 있을 수 있음을 설명한다. 스키마 통과와 내용 대조를 분리한다.

- 금액은 원화 수치/만원 표기를 정확한 정수로 비교한다. 여러 금액이 모순되거나 음수·미지원 표현이면 통과시키지 않는다.
- 사용처·목적·증빙 참조는 명시된 항목 또는 원문의 정확한 문자열 위치를 대조한다. 날짜는 명시된 ISO 날짜 또는 ‘지출일: 오늘/어제’만 변환하며 출장 기간을 지출일로 사용하지 않는다. 분류는 지원하는 비용 단어/enum과 대조한다.
- 명시적 후속 필드가 이전 필드를 대체한다. 구분되지 않는 정정·부정 표현은 보수적으로 질문으로 되돌린다. 동의어·복잡한 상대 날짜·다중 지출의 자동 해석은 검증 성공으로 표시하지 않는다.
- API의 `grounding.checks`는 INPUT_MATCHED/MISSING/UNVERIFIED와 원문 위치만 반환한다. 위치는 trim된 request/빈 답변을 제거한 answers의 Unicode code point 인덱스이며 sourceIndex 0은 request다. 원문을 별도 로그에 넣지 않는다.
- 대조되지 않은 필드는 후보에서 제거하고 필수값/불확실한 증빙 질문으로 전환한다. preview·확인 토큰·문서는 생성하지 않는다. 필드가 모두 대응해도 별도의 기존 업무 검증을 통과해야 미리보기를 만든다.
- 경비 제목·본문은 대조된 필드로 서버에서 다시 구성한다. 모델의 자유 문장에 없는 사실·정책 준수 주장을 숨겨 넣는 경로를 막는다. 일반·출장 초안은 이 경비 전용 검사 대상이 아니다.

프롬프트는 v5로 올려 사용처·목적·증빙 참조를 원문 그대로 추출하도록 했다. **기존 v4 실제 모델 36개 결과는 v5/새 검증기의 실제 모델 결과가 아니다.** 새 유료 실행 없이 합성 provider·실제 API와 회귀로 확인한다. V2를 일반화된 환각 방지/주입 방어로 주장하지 않는다.


V2 로컬 전체 API 617개 통과·34개 제외, mypy 199개 파일 통과. 실제 API의 경비 PC/모바일 작성→질문→미리보기→저장→수정→제출→승인 E2E 2개를 합성 provider로 통과했다. 마지막 질문 안내 보완 뒤 관련 API 회귀를 재확인한다. 기존 ‘grounded’ 테스트가 제공하지 않은 날짜·사용처를 fixture로 채웠던 부분은 입력에 실제 사실을 제공하도록 고치고, 같은 발명을 거절하는 별도 회귀를 추가했다.

## V3 정책·V4 화면/회귀 구현

경비 규정 검사는 인증된 기존 회사 정책 catalog의 활성·현재 시행·최신 버전만 사용한다. 검색 인용의 ID/버전/섹션/제목/원문을 catalog와 대조하고 불일치 시 policy 단계를 실패시켜 확인 토큰을 만들지 않는다. 날짜 기준은 Asia/Seoul이다. 모델 검색이 UNAVAILABLE여도 별도 DB 원문 catalog의 지원 규칙은 추가 유료 요청 없이 계산한다.

현재 자동 계산하는 규칙은 `RECEIPT_REQUIRED_MIN_TOTAL`이다. 금액이 기준 이상이면 원본 확인이 필요하다고 표시하며 참조 번호나 첨부 메타데이터를 원본 검증 성공으로 취급하지 않는다. 기준 미만은 해당 규칙 대상 아님이고, 다른 규칙/수기 조항/지원하지 않는 규칙 설정은 NOT_EVALUATED다. 전체 규정 준수 PASS/정확도 점수는 제공하지 않는다. catalog 인용의 similarityScore 0은 모델 검색 점수가 없는 직접 원문 참조다.

정책 fingerprint는 실제 원문·규칙 설정·버전·시행일을 포함한다. 새 경비 확인 토큰에 서명하고 첫 저장 직전에 재대조한다. 변경되면 409 POLICY_CHANGED로 재준비를 요구하며, 이미 성공한 같은 저장의 재요청은 기존 문서를 반환한다. 이전 경비 토큰에 fingerprint가 없으면 재준비가 필요하다. 이는 요청 간 변경 검사이며 동시 정책 발행 전체의 직렬화 보장은 아니다. 준비 단계는 문서를 쓰지 않는다.

화면은 입력과 일치/미입력/대조되지 않음, 규칙상 추가 확인/대상 아님/자동 판정하지 않음을 구분한다. 접을 수 있는 실행 정보는 단계 완료와 사실 검증 완료를 구분한다. 구형 서버에서 검증 정보 없는 경비 미리보기는 이 UI에서 AI 확인 저장을 차단하고 직접 작성을 안내한다. 서버의 JWT/검사 경계가 보안 기준이며 UI 숨김에 권한을 맡기지 않는다. 규정 변경 시 입력·후속 답변을 유지해 다시 준비한다.

오프라인 필수 평가 `uv run python -m app.evals.expense_verification`는 지원 baseline·6개 필드 변조·정정 뒤 이전 금액 재사용의 8개를 검사한다. 필수 실패 시 종료 코드 1로 CI validate를 차단한다. [고정 합성 결과](evidence/expense-verification-offline-2026-10-26.json)는 실제 모델 정확도·독립 holdout이 아니다. DB 설정·SDK를 import하지 않는 subprocess 회귀도 추가했다. 인용 변조·비활성 규정·정책 변경·저장 재요청은 별도의 실제 서비스/API 회귀로 확인한다.


V3/V4 최종 로컬 검증: API **623개 통과·34개 제외**, mypy **204개 파일 통과**, web lint/type 및 production build 통과. production PC/모바일 브라우저 **8개 통과**(경비 전체 처리 2개 + 검증 UI/구형 응답 차단/규정 변경 6개), 자동 접근성 검사 포함.
